# Структура проєкту

- `CalendarActivity.java` — стартовий екран, місячна сітка з понеділка, вибір дня, список подій, навігація місяців і видалення з підтвердженням. Читання бази й видалення виконуються у фоновому executor; застарілі відповіді не перезаписують новий вибір.
- `EventStore.java` — SQLiteOpenHelper для приватної бази `holoscalendar.db`, індекс за початком події. Оновлення виконується за ID, видалений запис не створюється повторно мовчки. Схема не використовує деструктивних міграцій.
- `SavedEvent.java` — збережений момент початку, первісний часовий пояс та необов’язкова тривалість; відображення подій, що переходять між днями, враховує DST.
- `ScreenInsets.java` — системні відступи обох екранів.
- `EventEditorActivity.java` — прив'язка XML-екрана, ручне редагування, відновлення форми, голосове введення та календарний intent. Основна дія зберігає у власну базу; зовнішній редактор відкривається окремо. Подія в зовнішньому календарі не вважається збереженою лише після його відкриття. ID редагованого запису зберігається при перестворенні Activity, щоб повторне натискання не створювало дубль.
- `VoiceParser.java` — незалежний від Android розбір української фрази. Використані фрагменти вилучаються один раз; решта тексту зберігає оригінальне написання. `ZonedDateTime now` передається явно для обліку DST; overload із LocalDateTime інтерпретує значення в UTC для детермінованих локальних тестів. Відносні команди повертають також точний Instant.
- `DurationParser.java` — явні вказівки тривалості, окремі від відносного часу початку. Відсутність тривалості представлена null, без прихованого значення за замовчуванням.
- `CalendarEvent.java` — перевірені дані події, часовий пояс, виявлення неіснуючого/повторюваного часу та тривалість у реальних хвилинах. Для відносної команди зберігається точний Instant, який не можна непомітно перенести на інше входження осіннього часу.
- `res/layout/activity_calendar.xml`, `activity_main.xml` — календар та форма; `res/values*` — тексти, кольори, стилі та темна тема; `res/drawable` — векторні іконки й фони.
- `src/test` — регресійні перевірки парсера та календарної моделі.
- `src/androidTest` — перевірки обробки результату розпізнавання й відновлення Activity на Android; вони виявляють несумісності, яких немає на настільному JDK.
- `gradle/wrapper`, `gradlew`, `gradlew.bat` — однакова версія Gradle для Android Studio, Windows, Linux і CI.

Нативний Java/Android SDK без обов'язкових зовнішніх UI-бібліотек. Стандартна бібліотека `java.time` доступна з minSdk 26. Application ID залишено `ua.holoscalendar.redmi` для сумісності з попереднім проєктом; версія 3.1.0 / versionCode 8. Потрібен той самий підпис для встановлення поверх попереднього APK.

Нові задачі розробки виконуються в наявному checkout; хмарна задача вже ізольована, створювати Git worktree без прямого прохання не потрібно.

Тривалість у CalendarEvent необов’язкова. EventEditorActivity передає EXTRA_EVENT_END_TIME лише за наявності валідної тривалості; інакше зовнішній календар сам визначає поведінку редактора.

SQLite зберігає тільки поля підтвердженої події, без вихідного тексту команди. Дозволи доступу до системного CalendarProvider не потрібні. Резервне копіювання вимкнено; системний та власний календарі не синхронізуються.

Launcher зберігає попереднє ім’я компонента `.MainActivity` через activity-alias, ціль якого тепер CalendarActivity. Це дозволяє старим ярликам відкривати новий календар після оновлення APK. Форма перейменована на EventEditorActivity.
